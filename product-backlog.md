# Product Backlog — Book Swap SA

**Module:** PRP372S — Project Presentation 3  
**Project:** Book Swap SA  
**Backlog tool:** Trello

## 1. Purpose

The Product Backlog is the organised list of work planned for the Book Swap SA project. It contains tasks covering project initiation, business planning, system analysis, UI/UX design, core system development, testing and finalisation.

The team's Trello board contains 54 day-based task cards organised around seven sprints.

## 2. Backlog Items

The following items are taken from the team's existing Trello board.

| Sprint | Planned work | Example tasks |
|---|---|---|
| Sprint 1 | Project Initiation and Business Planning | Develop the problem statement, identify stakeholders, conduct market research, analyse competitors and complete SWOT analysis. |
| Sprint 2 | Business Plan Development | Develop the mission and vision statement, define business goals, develop the business model and marketing strategy, and conduct risk analysis. |
| Sprint 3 | System Analysis and Design | Gather requirements, create user stories, design system architecture and database structure, and create diagrams and wireframes. |
| Sprint 4 | UI/UX Design and Prototype Development | Design the home page, registration page, user dashboard, textbook listings page, search and filter interface, and messaging interface. |
| Sprint 5 | Core System Development | Develop user registration, user login, profile management, textbook listings, search and filter functionality, and buyer-seller messaging. |
| Sprint 6 | Testing, Bug Fixing and Quality Assurance | Test registration, login, textbook listings, search and filter features, messaging, fix bugs and conduct user acceptance testing. |
| Sprint 7 | Project Finalisation and Submission | Complete technical documentation and the user manual, review the system, prepare the final presentation and live demonstration, conduct the project review and submit the final project. |

## 3. Prioritisation

The Trello board organises the work in a sequence from project initiation through development, testing and final submission. This sequence helps the team identify which activities should be addressed at each stage.

The detailed task order and progress are maintained in Trello.

## 4. Progress Tracking

Trello is used to display the project tasks, assign team members and track checklist progress. The board provides evidence of completed and outstanding work.

The status of each task should be checked against the current Trello board rather than assumed from the planned schedule.

## 5. Evidence

Screenshots of the actual Trello Product Backlog and relevant sprint lists will be included as supporting evidence. These screenshots show the task titles, sprint organisation and visible completion status.

The Trello board is the source of the project's backlog information.

## 6. Reflection

Working with the Product Backlog helped me understand how a large project can be divided into smaller activities and organised into a sequence of sprints. The seven-sprint structure shows how the project progresses from initial planning and requirements analysis to development, testing and final submission.

I also learned the importance of using Trello to organise tasks and monitor progress. Keeping the backlog organised helps the team understand what work is planned, what remains outstanding and which activities need attention. It is important to check the actual status of tasks rather than assume that planned work has been completed.

As the Frontend Developer, I can use the backlog to understand the features that need to be developed and how my work fits into the wider project. This helps me coordinate with other team members, prioritise my responsibilities and ensure that the interfaces I develop support the project's requirements.

Overall, the Product Backlog demonstrates the importance of planning, prioritisation and visibility when working as part of an Agile team.
